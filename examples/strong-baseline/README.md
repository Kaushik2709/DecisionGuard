# Strong baseline fixture

This planted checkout uses a mocked provider function and loopback HTTP. It makes no external
payment/model calls and establishes neither incremental product value nor incident frequency.

Install the pinned development tools once from this directory:

```powershell
npm.cmd ci --ignore-scripts --no-fund
```

Use Node 24 and the project's locked dev Python environment (explicit jsonschema 4.26.0).
From the repository root:

```powershell
uv run python examples/strong-baseline/run.py
uv run pytest tests/integration/test_strong_baseline.py -q --basetemp artifacts/strong-baseline-check
```

| Category | Actual checks |
|---|---|
| Schema | JSON Schema 2020-12 validator, valid examples and invalid controls |
| Codegen/types | openapi-typescript 7.13.0 freshness; TypeScript 5.9.3 strict no-emit compilation |
| Contract | Provider conversion and response schemas against consumer expectations |
| Integration | Node TypeScript client against Python HTTP API, including authentication |

`schema.d.ts` was generated by the pinned tool and checked in. To intentionally regenerate,
run `node node_modules/openapi-typescript/bin/cli.js openapi.json --output schema.d.ts` here and
review the diff. `run.py` checks freshness without rewriting source. Missing/wrong-version tools
are unsupported and exit 2, never a passing baseline. Check failures exit 1. The runner installs
nothing. `--tools-root` can reference this directory's installed tools from a copied worktree.

The paired regression retains its fixed plan, starting-source fingerprints, actual logs, runner/
gate records and report under its pytest temporary `study` directory. Both arms catch the planted
client-only 499 -> 49900 unit change through HTTP. Schema and types allow it because both values
are numbers. Zero extra detections are credited to DecisionGuard; the benign case passes both.
A wrong string field separately fails the real compiler. This is not a volunteer or downstream
Git-integration study; escaped-defect rates remain unknown.
